## Implementation and reasoning

- Authorization still uses the actual authenticated owner route and nondisclosing non-owner response. Authorization session closes before the service transaction; service rechecks ownership under lock.
- First service read locks the same existing `MeetingProcessingClaim` row as both workers with PostgreSQL `FOR UPDATE NOWAIT`. A missing/legacy row cannot be manufactured into eligibility. Missing generation, any claim metadata (even expired/incomplete), prior operation, generated output or uncertain probe rejects without writes.
- Locks meeting, singleton gate and exactly one persisted recording within the same transaction. Runtime must be pilot + exact allowlist and a matching unused, explicitly armed persisted gate. This API cannot arm/rearm a gate.
- Generated-output roots checked: transcripts, diarizations, speaker reviews, meeting summaries, summary request outbox and processed summary ledger. Turns, speakers, assignments and review children require these roots via FKs. Existing title/note, recording, retention/consent and unrelated rows are not modified.
- Requires nonempty canonical persisted audio reference, unexpired recording, and successful metadata-only object availability. Never downloads audio, calls engines or checks broker counts.
- Once all guards pass: increment generation, bind recovery claim, persist narrow `guarded_manual_recovery` event through `record_transition` with history to `transcribing`, one hashed-idempotency operation, one content-free pending outbox (`transcribe`), and gate `running` together. Flush or commit error rolls all of these back. Raw idempotency key/media references are never persisted in recovery rows.
- Delayed old-generation and legacy messages are demonstrably fenced after generation advance, not assumed absent because of an empty queue. Active/uncertain claims always reject. Same actor/meeting/key returns the original operation without mutation; another key cannot consume the gate again. NOWAIT contention is a conservative no-op, not an automatic retry.
- The precursor's pilot fixture has no fence; its exact expected no-op reason is now `eligibility_unverified` instead of the temporary unconditional `pilot_not_armed`. All content/no-write/auth assertions are retained. Default/disabled/invalid modes still return `pilot_not_armed`.
