## Two practical options

| | 1. Local-first: Ollama on Fer's Mac | 2. Cloud API: OpenAI `gpt-6.1-terra` |
|---|---|---|
| **Data boundary** | With a local model and a local-only endpoint, transcript text stays on the Mac; do not use an Ollama cloud model or add silent cloud fallback. This is the privacy-first candidate. Local processing does not itself establish Sauri access control, disk protection, or device security. | Minimal transcript text is sent over TLS to OpenAI's API; it leaves the Mac and is processed on provider infrastructure. OpenAI states API data is not used to train models by default, but its data-controls page says abuse-monitoring logs may contain prompts/responses and are retained up to 30 days by default; eligible retention controls require approval and have limitations. This is not equivalent to local processing. Review the applicable terms, retention controls, account/region configuration, and organizational approval. Send no audio/video, identity, template name, or unrelated metadata. |
| **Resources, latency, quality** | Uses Mac memory, compute, disk, and power; speed and context capacity depend on hardware, model/context size, and concurrent load. No network inference hop, but local inference can be slower or compete with other work. Output quality for Sauri's Spanish commercial transcripts is unverified and must be assessed with synthetic cases before any private-recording trial. | Requires network and provider availability; end-to-end latency varies with network, request size, and service load, but avoids consuming local inference resources. Model suitability for Sauri's Spanish transcripts is also unverified and needs the same synthetic evaluation; do not treat model capability as a quality guarantee. |
| **Cost estimate** | No per-token API charge for local inference. There is still hardware opportunity cost, electricity, model storage, and maintenance; model files already present are sunk local storage, not a zero-cost guarantee. | Public list price checked 2026-10-30: `gpt-6.1-terra` standard input $1.00 / million tokens and output $5.00 / million tokens. Illustrative, not a forecast: 10,000 input + 1,000 output tokens ≈ $0.015 per summary; ≈ $1.50 per 100 summaries. Actual tokenization, prompt/context overhead, retries, price changes, taxes, and other account charges may change this. |
| **Failure/auth seam** | Bind the worker only to an explicitly configured local base URL/model; fail closed if unavailable or misconfigured. No automatic cloud fallback. Local-server failure/timeout follows the existing queue retry boundary; surface a safe terminal failure, not raw provider details. No API key is needed for a local-only Ollama endpoint, but endpoint exposure/access still needs configuration review. | Bind via explicit model and endpoint configuration; hold the API key in deployment secrets (never source, logs, or task artifacts), require TLS, and fail closed on missing credentials. Network/timeout/rate-limit/provider failures use bounded queue retries and safe terminal status without disclosing provider error details. Never silently switch to the local model. |

## Evidence and recommendation

A read-only check on 2026-10-30 found `/usr/local/bin/ollama`; `ollama list` reported `qwen2.5-14b-4k:latest` (9.0 GB), `qwen2.5:14b` (9.0 GB), and `bge-m3:latest` (1.2 GB). This verifies the CLI and local model inventory only—not that Ollama's server is running, the Mac has sufficient inference memory, the model produces acceptable summaries, or Sauri is bound to it. No generation request was made and no private recording was used. Ollama's macOS guidance notes local speed depends on hardware and large models can be slow without a strong GPU.

**Recommendation to consider:** prefer option 1 for a privacy-first evaluation because Fer reports Ollama is installed and local models are present. Start with synthetic fixtures only; verify server/configuration, resource use, latency, and usefulness before any decision about real meeting data. This is not a provider selection or production authorization. If local feasibility or quality is inadequate, option 2 is a concrete alternative, but using it requires explicit approval of the data transfer and cost as well as verified credentials/configuration. Fer alone chooses the binding; any privacy, cost, or product-policy decision remains with the authorized owner process.
